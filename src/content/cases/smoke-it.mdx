## 禁煙を押し付けず、習慣を記録して振り返る PWA

喫煙本数や支出を記録して自分の習慣を振り返ろうとしたとき、既存の禁煙・節煙アプリにはいくつかの不満がありました。初期登録の手数が多く、画面デザインも警告的・医療的すぎて開くのが億劫になる点です。また、公開当初は禁煙を目指すアプリとして作っていたものの、運用を続けるなかで「吸わないように促すのではなく、吸った本数をそのまま記録してあとから振り返る」方針へ舵を切りました。

そこで、スマホのホーム画面から開いて、手元の箱から 1 本ずつ取り出すように記録でき、銘柄・写真・支出の推移を気軽に振り返れる PWA として作り直しました。

## 習慣記録アプリが抱える壁

- 地下鉄や飲食店などの電波が届きにくい場所でも、待ち時間なく記録でき、あとから重複せずに同期できること
- 単なる数値入力に終わらず、箱の減り具合や写真、グラフで自分の行動傾向を把握できること
- スマホ片手で迷わず記録でき、誤タップしてもすぐ取り消せること
- 記録をためるだけでなく、自分のデータをもとに傾向を整理・相談できる対話機能があること

## 技術選定: TanStack Start・React Three Fiber・カスタム Service Worker

フロントエンドとバックエンドの境界を減らすため、TanStack Start（Vite + SSR + TanStack Router）と React 19、Tailwind CSS v4 を採用しました。ランタイムはローカルで Bun、本番で Node.js 22 を使っています。

認証には Auth.js（`@auth/core`）と Google OAuth、データ永続化には PostgreSQL と Prisma 7 を組み合わせ、ユーザーごとの記録・銘柄・箱・設定を型安全に管理しています。

ホーム画面の 3D 表現には React Three Fiber と Three.js、UI アニメーションには Framer Motion、グラフ描画には Recharts を採用しました。PWA 基盤はカスタム Service Worker（`src/sw.ts` を `esbuild` でビルド）と IndexedDB によるオフラインキュー、Web Push API（VAPID）で構成しています。

AI コーチ機能は OpenRouter API を介し、ユーザーの直近の記録傾向や開封中の箱、支出を踏まえたアドバイスをストリーミング（SSE）で返す構成にしました。

## 体験と継続を支える設計

### 3D の箱・着火演出・灰皿による記録体験

ホーム画面では木の机の上に手元の箱と灰皿を 3D で表示し、箱から 1 本ずつ取り出して記録します。紙巻きだけでなく加熱式の 2 列に分かれた箱にも対応しており、使いかけの箱もいまの残り本数から始められます。

1 本を記録すると、紙巻きはオイルライターで火をつけてひと吸いでフィルターの手前まで吸い、加熱式は蒸気を出してから灰皿に置くところまで 3D で動きます。その日に吸った本数だけ灰皿に吸い殻やスティックがたまり、日本時間の 0 時に空になります。

記録直後には「取り消す」操作を出して誤タップの手戻りを減らし、写真付き記録のボタンからはそのままカメラを開けるようにしました。

### 箱棚コレクションと写真からのドット絵生成

開けた箱は「箱棚」に並び、種類ごとの絞り込みや集まり具合を見ながら管理できます。銘柄の管理も箱棚に統合しました。

パッケージの絵柄はテンプレートやドット絵エディタで描けるほか、実際の箱の写真を撮ってドット絵を生成し、そのまま手直しして箱に貼り付けられるようにしています。

### オフライン記録と冪等な同期、カスタム Service Worker

圏外や機内モードでも記録が途切れないよう、オフライン時は 3D の引き抜き演出に入る前にまず IndexedDB のキューへ保存し、通信復帰時に自動で同期する構成にしました。各操作にはクライアント側で `operation_id` を振り、サーバー側の `ProcessedLogOperation` テーブルで処理済みを管理することで、再送による二重登録を防いでいます。

カスタム Service Worker では `/api/uploads/` の記録写真を Cache First でキャッシュし、ログアウト時にはキャッシュを破棄します。あわせて Web Push の受信と通知タップ時の遷移もここで処理しています。

### カレンダー・傾向分析・落款印の実績

記録帳のような落ち着いた組み方で、1 日のタイムライン、月間カレンダー、週間レポート、曜日・時間帯別の傾向グラフ、銘柄価格にもとづく支出推移を一覧できます。

実績バッジは和紙に押す落款印として作り直し、「吸わなかった日数」で称える仕組みをやめ、記録を続けたことや変化を振り返る設計に揃えました。

### 記録・開封中の箱・支出を踏まえた AI コーチ

一般的な禁煙アドバイスを返すのではなく、ユーザー自身のデータを踏まえて対話できる AI コーチを組み込みました。

システムプロンプトには、記録開始日、直近 7 日間の平均、直近 4 週間の日別記録に加えて、現在開封中の箱（箱番号・銘柄・残り本数・消費ペース）と直近の支出サマリーを動的に渡します。過去の会話の切り替えにも対応しています。

また、OpenRouter の無料枠モデルは予告なく提供終了することがあるため、実測で安定していたモデル候補を順に試すフォールバックと、環境変数からデプロイなしで先頭モデルを差し替えられる仕組みを入れました。

### データ設計と更新履歴の一元管理

Prisma スキーマでは、`UserSettings`、`Brand`、`Pack`、`Log`、`ProcessedLogOperation`、`UserBadge`、`CoachMessage`、`PushSubscription`、`PendingNotification` を定義しています。

`Log` には時系列集計のための `(userId, created_at)` インデックスに加え、箱内のスロット重複を防ぐ `(packId, slot_index)` の一意制約と、画像配信時の所有権確認を高速化する `(userId, image_url)` インデックスを設定しています。

ユーザー向けの更新内容は単一のリスト（`src/lib/changelog.ts`）で管理し、[公開の更新履歴ページ（`/changes`）](https://smoke-it.koshikai.dev/changes)、設定画面のお知らせ、ホーム画面の未読チップをすべて同じデータから生成しています。

## 開発・運用を通じて得た知見

- **記録の即時性とオフライン冪等性はセットで効く:** 通信待ちを出さず、演出の前にローカルキューへ保存して `operation_id` で重複を防ぐ設計にしたことで、電波が不安定な場所でも安心して使い続けられるようになりました。
- **AI へのコンテキストは絞り込み、外部モデルの障害に備える:** 全期間のログを渡すより、直近 4 週間の集計・開封中の箱・支出に絞って渡す方が応答が安定します。さらに無料モデルの一斉提供終了を実際に経験したことで、候補リストによるフォールバックと環境変数での差し替えが運用上の必須要件になりました。
- **方針転換は UI・言葉・実績まで一貫させる:** 「禁煙を目指すアプリ」から「吸った本数を記録して振り返るアプリ」へ方針を変えた際、目標本数表示や「吸わなかった日数」の実績も合わせて整理したことで、画面の言葉と体験のズレがなくなりました。
